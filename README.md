# A Lean proof of BCMP Conjecture 4.30

**TL;DR.** Fix any integer $s\ge 2$ and put $h=s/(s+1)$. Every untuned parameter other than $h$ is accumulated by infinitely many **distinct non-neutral matching intervals** of the original family $Q_\gamma$. The formalization includes the endpoint $0$. It does not assume that the parameter's orbit eventually reaches $h$.

[Original conjecture (author PDF, §4.5)](https://www.mat.univie.ac.at/~bruin/papers/bcmp.pdf) · [Paper ↔ Lean: a one-page guide](docs/paper-to-lean.md) · [Final theorem](formal/Final430.lean#L31-L38) · [Expanded statement](checks/VerifyStatement.lean) · [中文证明](docs/proof-zh.md)

**Provenance.** The conjecture is by Henk Bruin, Carlo Carminati, Stefano Marmi and Alessandro Profeti. The proof presented here and its Lean formalization were generated by AI. The repository maintainer selected the problem and made the artifacts available; the maintainer is **not** claiming authorship of the proof. A separate AI review compared the formal statement with the authors' text and repeated the build. This is not human peer review or an endorsement by the conjecture's authors.

## For a mathematical reviewer

The question on which human feedback would be most valuable is: **does the formal statement capture Conjecture 4.30 as you intended it?** The [correspondence guide](docs/paper-to-lean.md) compares the untuned set, the one-sided derivatives and the meaning of accumulation. To see precisely what Lean accepted, read the [expanded theorem and axiom output](docs/verification/statement-and-axioms.txt). The published article is [*Matching in a family of piecewise affine maps*](https://doi.org/10.1088/1361-6544/aae935); the earlier formulation is in [arXiv:1707.07488](https://arxiv.org/abs/1707.07488).

## Reproduce the check

**Requirements:** Git, Python 3.11 or newer, and the pinned Lean **4.36.0** toolchain with its matching Lake. In a fresh clone, run from the repository root with that toolchain active:

```sh
lake build checkLakePins
lake exe checkLakePins
lake exe cache get Mathlib.Analysis.SpecificLimits.Basic Mathlib.Tactic.FieldSimp Mathlib.Tactic.Linarith Mathlib.Tactic.Ring
python verify.py --lean "$(elan which lean)" --out ../bcmp-full
```

`../bcmp-full` must not already exist. With a standalone Windows toolchain, the last command can instead be `py -3 -X utf8 verify.py --lean "<toolchain>\bin\lean.exe" --out "..\bcmp-full"`. Pass the real binary, not an elan shim. An optional `--preflight-only` in a separate new directory checks dependencies, **not** the proof. If certificate validation fails while fetching dependencies, fix the TLS/network setup; do not disable certificate checks.

Both the main check and the independent replay compiled all **45 project modules** from source with warnings treated as errors, then compiled a separate consumer that applies the theorem with the quantifiers expanded. Both exited `0`. The final axiom report was:

```text
'BCMP430.Final430.bcmp_conjecture_4_30' depends on axioms: [propext, Classical.choice, Quot.sound]
```

The [verifier](verify.py) checks the [proof source hashes](formal/sources.sha256), consumer hash and nine locked dependency checkouts. It uses the official Lean toolchain and trusts the matching dependency build cache; it does not use prebuilt project objects. On success, the new output directory contains `build.log` and `statement-and-axioms.txt`.
